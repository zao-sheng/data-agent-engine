# Plan：意图分类 → 路径选择

任何用户请求，先做规划，**确定路径后再执行**，不要直接跳到翻译/执行。

## Step 1 · 意图分类（四类，逐条判定）

| 意图 | 判定（用 `mcp__dataagent__metadata_search` / `ontology_search` 辅助） | 路径 |
|------|---------|------|
| **取数** | 用户要**查数据/看数值**（如"昨天 GMV 多少"） | A → `query-metric`（缺指标维度则转 D） |
| **元数据咨询** | 找表、找指标维度、了解表加工逻辑、指标口径、表就绪时间、血缘关系 | 元数据检索（`metadata_search`，必要时 `ontology_search/traverse` 补充） |
| **新建/建模** | 新建表、ETL 任务、指标维度、本体信息（含"缺指标维度要求新建"） | D → `modeling-etl` → `modeling-workflow` |
| **其他操作** | 修改 ETL、修改调度参数、调整口径逻辑等存量变更 | 直接调用对应 MCP（`etl_generate`/`scheduler_submit` 等），按工具约束执行 |

> 判定要点：**取数 vs 元数据咨询**的区别是「要数值结果」还是「要元信息」。
> 用户说"查 GMV" = 取数；用户说"GMV 怎么算/哪张表有 GMV" = 元数据咨询。

## Step 2 · 取数子流程（关键分支：缺指标维度 → 询问是否新建）

```
取数意图
  ├─ 用户要的指标 + 维度全部已注册？
  │    是 → A（load query-metric skill，正常取数）
  │    否 → 明确告知用户：未找到「指标 X / 维度 Y」的注册信息
  │           ├─ 询问是否新建（ask_user_question）
  │           │    ├─ 是 → D（load modeling-etl skill，走建模全流程）
  │           │    └─ 否 → 结束，不查询不编造
  │           └─（不得自行降级/拼接/臆造未注册的指标或维度）
```

## Step 3 · 选择执行路径（确定性规则，按序判定）

```
① 取数意图？
     → 指标+维度齐全 → A（query-metric）
     → 缺失 → 询问是否新建 → 是走 D / 否结束
② 元数据咨询意图？
     → metadata_search（+ ontology_search/traverse 补充解读）
③ 新建/建模意图？
     → D（modeling-etl → modeling-workflow）
     → ⚠️ 进入 D 后【第一步】必须先输出完整的需求识别清单（编号表格），
       再一次性 ask_user_question 整体确认——不得先逐项追问
④ 其他操作（改 ETL/调度等）？
     → 直接调用对应 MCP，遵守工具约束与审批
⑤ 无法归类的复杂请求？
     → 先 metadata_search 查重，再按上述规则归类；
       仍无法归类 → 向用户澄清意图，不臆断
```

## 硬性规则
- **取数必须走 A 流程**（OAG → MQL → 确认 → 翻译 → 执行），不允许自我发挥、
  不允许绕过工具直接编造结果。
- **缺指标/维度**：只告知缺失 + 询问是否新建，**不得**用近似指标/字段替代查询。
- 元数据咨询不产生数值结果，只解读元信息（口径/血缘/就绪时间）。
- 新建类需求必须走 D 的阶段化流程（先报告 → 确认 → 执行）。
- 存量修改（改 ETL/调度）直接调工具，但涉及口径变更仍需用户确认。

## Step 4 · 输出执行计划
用一句话说明：意图 / 路径 / 是否缺指标维度 / 是否需要用户确认，然后加载对应路径的 skill 或调用对应工具。
