# 探索性查询（受限兜底）

## 触发条件（全部满足才允许，缺一不可）
1. 用户取数意图，但**指标/维度缺失**（`metadata_search` / `ontology_search` 确认未注册）；
2. 已询问是否新建（`ask_user_question`），用户**拒绝新建**；
3. 用户**仍明确要求**探索性答案（如"先大概看看有哪些数据"）；
4. 用户**显式同意**走探索路径（不能默认允许）。

> 任何一条不满足 → 不进入本流程：缺指标且拒绝新建 → 直接结束；
> 用户要新建 → 走 D（`modeling-etl`）。

## 流程
1. **候选表召回**：`mcp__dataagent__metadata_search` + `ontology_search` + `ontology_traverse`
   找到最接近的事实对象与表；不猜表名（物理表只出现在工具返回中）。
2. **受限生成**：直接编写 SQL（仅 SELECT；只允许白名单函数；必须带 dt 分区条件；
   必须带 required_filter（is_valid=1 等）；行数 ≤ 1000）。
3. **校验**：先经 `mcp__dataagent__mql_validate` 语义层自查（不含物理表名），
   再在只读沙箱执行（SQLite 只读模式 + 行数上限）；探索 SQL 不经过翻译令牌链
   （该链仅服务注册指标），但执行仍受只读执行器强制约束。
4. **人工确认标记**：回答必须声明：
   「⚠️ 探索路径生成（非注册口径），建议人工核对后使用」
5. **治理反馈**：把该查询记入反馈（供 Ontology 治理补充映射/注册指标）。

## 禁止
- 禁止写库/DDL/任何非 SELECT 语句；
- 禁止把物理表名/字段名作为「口径」告诉用户；
- 禁止绕过校验链直接返回；
- 禁止在用户未显式同意探索时自动走本路径（默认走 query-metric 或结束）。
